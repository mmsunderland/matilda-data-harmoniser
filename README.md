# Data Harmonisation Assistant

A Shiny app for harmonising variables across multiple survey datasets. Define constructs (the variables you want in your output), assign the corresponding variable from each dataset, align response codes where needed, and download a ready-to-run R harmonisation script.

Supports cross-sectional and wave-structured (panel) data. Works with Stata `.dct` dictionary files directly, or with enriched pipeline output that adds domain classification and cross-dataset match suggestions.

---

## Quick start

### 1. Install required packages

```r
source("setup.R")
```

Or manually:

```r
install.packages(c("shiny", "bslib", "DT", "dplyr", "haven", "readr", "tidyr", "purrr"))
```

### 2. Add your dictionary files

Place one Stata infile dictionary (`.dct`) per dataset into the `dct/` folder. The filename (without `.dct`) becomes the dataset label in the app.

```
harmoniser/
  dct/
    study_a.dct
    study_b.dct
    study_c.dct
```

### 3. Launch the app

```r
shiny::runApp("harmoniser/")
```

## Data modes

| Mode | How to trigger | What's available |
|------|---------------|-----------------|
| **Pipeline mode** (recommended) | Place `domain_labels.csv` and `harmonisation_candidates.csv` in `output/final/` | Domain/subdomain labels, cross-dataset match clusters, compatibility indicators |
| **DCT-only mode** (fallback) | No pipeline output found | Variable browsing only; no match suggestions or domain labels |

Pipeline output is generated by `dict_pipeline`, a separate LLM-based preprocessing step.

## App layout

The app has two top-level views, toggled by the nav buttons in the header:

- **🗂 Construct Manager** — define constructs, track assignment progress per dataset
- **🔍 Variable Search** — search for variables to assign to a construct

A **detail panel** slides up from the bottom of the screen when you open a construct. It has three columns:

| Column | Purpose |
|--------|---------|
| **1. Construct settings** | Edit name, label, domain, subdomain, notes |
| **2. Dataset assignments** | Confirm which variable each dataset uses for this construct |
| **3. Response code alignment** | Check and align response coding across datasets |

## Workflow

### Step 1 — Define constructs

A **construct** is the harmonised variable you want in your output (e.g. `k10_total`, `age`, `sex`).

Add constructs in the Construct Manager via:

- **+ Add construct** — creates a blank construct
- **Type or paste construct names** — comma-separated, added in bulk (empty state)
- **Import from CSV** — CSV with `harmonised_name` column (optional: `harmonised_label`, `domain`, `subdomain`)
- **Load pipeline clusters** — imports all clusters from pipeline output, pre-assigning variables where a match was found

### Step 2 — Assign variables

Open any construct using **Edit / Review →**. In **Column 2** of the detail panel, each dataset in your data is listed with its current assignment status.

**Badge colours** (also shown in the Construct Manager):

| Colour | Meaning |
|--------|---------|
| Green | Confirmed — variable assigned, no recode needed (or recode confirmed) |
| Amber | Pending — response code differences detected, review Column 3 |
| Grey | Unreviewed — not yet assigned |
| Light/striped | Excluded — dataset deliberately excluded for this construct |

**Actions per dataset row:**

| Action | When shown | What it does |
|--------|-----------|--------------|
| 🔍 Find variable | No variable assigned | Opens Variable Search pre-filled with the construct name |
| ✓ Confirm | Variable assigned, status unresolved | Manually marks as confirmed (no recode needed) |
| Change | Variable assigned | Re-opens search to pick a different variable |
| Excl. | Variable assigned or unreviewed | Marks dataset as excluded (output will be `NA`) |
| Include | Currently excluded | Re-includes the dataset |

#### Variable Search

When you click **Find variable**, the search view opens with:

- The **dataset pre-selected** in the dropdown
- The **search box pre-filled** with the first four words of the construct label (or the harmonised name if no label is set)

Results update automatically. Click **✓ Assign** on the correct variable to confirm and return to the construct.

Click **← Back to construct** to cancel without assigning.

#### Automatic recode status

When you assign a variable, the app immediately evaluates whether a recode is needed:

- **confirmed** — variable has no value labels (numeric), or response codes are identical across all assigned datasets
- **pending** — code values or labels differ across datasets
- **unreviewed** — could not determine (all comparison partners lack label data); a **✓ Confirm** button appears in the row

Assigning a new variable also re-evaluates all existing `confirmed` assignments for that construct — if the new variable introduces a coding conflict, previously confirmed datasets are demoted to `pending`.

### Step 3 — Align response codes

**Column 3** of the detail panel shows a response-code matrix across all assigned datasets.

If coding is identical, a green notice appears and no action is needed.

If differences are detected:

1. Check the matrix — amber cells differ from the reference dataset
2. Set the **Reference** dataset (the coding you want to keep)
3. Click **Auto-generate** to propose new codes by matching label text
4. Edit any rows where the suggestion is wrong
5. Click **Confirm all** — all `pending` assignments turn `confirmed`

### Step 4 — Download the R script

Click **⬇ Generate .R** in the header. The button turns green when all constructs are confirmed.

Set `data_folder` at the top of the downloaded script to point to your actual data files before running.

To generate code for a subset of constructs, tick the checkboxes in the Construct Manager and use **Show selected only**, then download.

## Construct Manager features

### Progress tracking

The header bar shows: total constructs · complete · pending · issues (clickable to scroll to first matching construct).

A colour-coded progress bar summarises overall status.

### Domain grouping

Constructs are grouped by domain in collapsible sections. Click a domain header to expand/collapse.

### Inline editing

Double-click any construct **name** or **label** in the list to edit it in place.

### Selection

Tick the checkbox on any construct row to select it. Use **Show selected only** to filter the list. Selected constructs can also be exported or used to scope the generated R script.

### Export mapping

**Export CSV** downloads a spreadsheet of all constructs and their dataset assignments.

## Wave variables

Wave-structured datasets (variables like `T1_age`, `T2_age`, `T3_age`) are automatically detected and collapsed. When you assign a base variable (e.g. `age`), all its wave variants are automatically included in the generated output — you do not need to assign each wave separately.

Wave coverage per construct is shown at the bottom of **Column 1** in the detail panel.

Detected prefixes: `T{n}_`, `W{n}_`, `t{n}_`, `w{n}_`, `Time{n}_`, `Wave{n}_`.

---

## Auto-save and session restore

The app auto-saves your session every 30 seconds to `output/final/app_state.rds`. If you close and reopen the app, a prompt offers to restore your previous session.

## Generated script structure

The downloaded `.R` file contains:

1. **Setup** — `library()` calls, `data_folder` path, `person_id_col`, `load_dataset()` helper
2. **Per-dataset blocks** — `select()` + `rename()` for each dataset; wave datasets use `pivot_longer()` with `names_pattern`
3. **Confirmed recodes** — `mutate(case_when(...))` blocks for any confirmed recode rules, with original/new code comments
4. **Combine** — `dplyr::bind_rows()` across all datasets + summary `cat()`
5. **Value labels** — commented reference section listing response code sets
6. **Save** — commented `saveRDS` / `write_dta` / `write.csv` options

### Standard output columns

| Column | Content |
|--------|---------|
| `source_dataset` | Dataset name |
| `wave` | Integer wave number, or `NA` for cross-sectional data |
| `person_id_col` | Value of the ID variable set at the top of the script |

Followed by all harmonised variable columns in construct order.

## .dct file format

```
dictionary {
  int   id            `"Respondent ID"'
  byte  age           `"Age in years"'
  byte  sex:SEXLABEL  `"Sex of respondent"'
}

label define SEXLABEL 1 "Male" 2 "Female"
```

Value label sets are parsed and shown in the Variable Search results and in Column 3 of the detail panel. They are also emitted as commented documentation in the generated R script.
